## 3. Ce qui a été fait, fonctionnalité par fonctionnalité

### 3.1 F2 — extraction de clauses avec un Transformer
- **Modèle** : `nlpaueb/legal-bert-small-uncased` (préentraîné sur des textes juridiques), affiné sur
  nos segments. Deux modèles (D-013) : 3 familles sur CUAD, confidentialité sur ContractNLI.
- **Leçon 1** : un **poids des positifs** trop fort (≈ 100, car 1 % de positifs) fait dire « oui » trop
  souvent (F1 0,506) ; atténué (racine, ≈ 10) → 0,625.
- **Critère de sélection fixé avant le test** (D-012, Sara) : **rappel par annotation maximal sous
  précision ≥ 0,50 par famille**, appliqué **sur la validation**. Résultat famille par famille :
  Transformer pour la durée (0,909) et la responsabilité (0,879), TF-IDF pour la résiliation (0,640).
  Rappel macro **0,809** (TF-IDF partout : 0,794) — écart petit et chiffre optimiste (choix sur la
  validation) : **seul le test, ouvert une fois, donnera la référence**.
- **Confidentialité** : F1 0,862 ; seuil **0,95** retenu par **exception écrite** au critère (D-019 :
  réglé sur des NDA, appliqué à des contrats commerciaux).

### 3.2 F4 — inférence en langage naturel (NLI)
- Pour un accord et une hypothèse (« Receiving Party shall not reverse engineer… ») : *Entailment*,
  *Contradiction* ou *NotMentioned*, avec les **phrases d'évidence** citées.
- Méthode (D-014) : le modèle juge chaque paire (hypothèse, phrase), puis on décide pour l'accord ;
  sans phrase assez probante → *NotMentioned* (abstention).
- Dev : exactitude **0,778**, macro-F1 0,717 (classe majoritaire : 0,681 / 0,633) ; la contradiction
  reste la plus difficile (F1 0,575).

### 3.3 F5 — questions-réponses
- **Recherche hybride** dans PostgreSQL : mots (texte intégral) + sens (bge-small + pgvector), fusion
  RRF. **Recall@5 0,586** (mots 0,518, sens 0,543) ; Recall@10 0,682.
- **Extractif avec abstention** : faible (exactitude équilibrée 0,521 ; « toujours s'abstenir » : 0,5).
  Leçon : l'exactitude simple récompense l'abstention quand 2/3 des questions n'ont pas de réponse →
  critère **équilibré** (D-017, choisi après l'échec du premier, sur la validation seulement).
- **RAG LangGraph + LLM local** (qwen3-vl:8b via Ollama) : chercher → générer → **vérifier chaque
  citation mot pour mot** → répondre ou s'abstenir. Mesure **indicative** (20 questions) : exactitude
  équilibrée **0,643** (extractif 0,423), **0 réponse fausse**, 13/13 abstentions correctes, mais 2
  réponses trouvées sur 7 et 82 s par question.

### 3.4 F3 — alertes entre clauses (préparation de l'annotation humaine)
- **47 paires** de clauses d'un même contrat (validation), 4 types ; références seulement dans le dépôt.
- Grille de 4 étiquettes, guide, **kappa de Cohen** ; annotation par **Sara et Ilyas**, indépendamment.
- **Règle v1 figée avant les annotations** (date du commit) : 41 alertes sur 47 ; le NLI ne se
  transfère pas aux paires de clauses → **risque n°1 du cahier des charges** ; plan de repli :
  présenter F3 comme **étude expérimentale** si les annotations confirment (D-018).

### 3.5 F6 — l'application
- **API FastAPI** (`src/cg/api/`) : import d'un PDF, clauses, questions (extractif ou LLM), alertes
  (expérimental), hypothèse NLI ; **avertissement** dans chaque réponse ; **page et positions** de

## 4. Les notions nouvelles, expliquées simplement

- **Affiner un modèle préentraîné** : Legal-BERT connaît déjà la langue juridique ; on lui ajoute une
  petite « tête » de classification entraînée sur nos segments. **Époque** = un passage sur le train.
- **Poids des positifs** : compense la rareté des clauses ; trop fort, il crée des fausses alertes.
- **Critère fixé avant le test** : on choisit le modèle **sur la validation** ; le test ne sert qu'à
  rapporter le chiffre du modèle déjà choisi (règle 2).
- **Comparer à précision égale** : on fixe « au moins une alerte sur deux juste », puis on regarde
  qui trouve le plus de clauses.
- **NLI** : implique / contredit / n'en parle pas ; la phrase la plus probante est citée.
- **Embedding** : un texte devient une liste de nombres ; des sens proches donnent des listes proches.
- **Recherche hybride et RRF** : additionner les rangs d'une recherche par mots et d'une par sens.
- **RAG** : chercher des passages, faire répondre le LLM à partir d'eux seulement, **vérifier** les
  citations ; **LangGraph** décrit ces étapes comme un graphe.
- **Modèle « thinking »** : il écrit une réflexion avant de répondre ; à température 0, il peut
  boucler ; une **graine fixe** garde la reproductibilité avec une température de 0,6.
- **Exactitude équilibrée** : moyenne « bonnes réponses » / « bonnes abstentions » (0,5 pour un
  système qui s'abstient toujours).
- **Kappa de Cohen** : accord entre deux annotateurs, corrigé du hasard.
- **API** : des adresses web qui exposent des fonctions ; **React + Vite** : l'interface qui les appelle.

## 7. Limites, risques et erreurs

**Limites**
1. **Aucun chiffre de test** : il faudra une décision écrite pour ouvrir le test de F2, puis de F4 et F5.
2. **LLM mesuré sur 20 questions seulement**, avec un modèle qui réfléchit toujours (82 s par
   question, 1 sortie sur 4 inutilisable) ; mesure de référence à refaire avec `qwen3-vl:8b-instruct`.
3. **F3 non évaluée** tant que Sara et Ilyas n'ont pas annoté ; règle v1 très peu sélective.
4. Confidentialité apprise sur des NDA ; appliquée à des contrats commerciaux (D-019).
5. Pas d'OCR : une page scannée est signalée mais pas lue (extension prévue avec Qwen-VL).
6. Interface minimale (un écran), sans comptes utilisateurs.

**Risques de méthode**
- Fusions sans relecture d'Ilyas (**PR #2 à #13**), dont des changements de règles communes.
- Choix « meilleur modèle par famille » et critère d'abstention décidés après avoir vu des résultats
  de validation : écrit noir sur blanc dans D-012 et D-017.

**Erreurs de Claude, détectées et corrigées (journal)**
- Progression invisible (Python sans `-u`) ; grille de seuils trop courte (séance 1).
- Critère d'abstention mal choisi (exactitude) ; un `python3` interdit dans une commande ; bug des
  tests de la base qui laissaient des contrats (séance 3).
- Calculs lancés en même temps que le LLM ; noms de paramètres MLflow avec accents (séance 5).
